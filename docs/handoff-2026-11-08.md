## 1. 项目是什么

一个**可交互的生化代谢图册**：每条代谢通路一张数据驱动 SVG 挂图，分子可点开看 2D 结构式与 3D 结构对照，所有化学资产离线生成，运行时只做「数据 → 版面 → 交互」，不在浏览器里跑化学计算，也无后端。

> **当前状态（截至 2026-11-10，实测）**

- 技术栈：**Vite 6.4.5 + React 18 + TypeScript 5（`strict` 全开，含 `noUnusedLocals` / `noUnusedParameters`）+ react-router-dom 7 + 3Dmol.js**。
- 规模：**23 张挂图（PLATE 00–22）**：PLATE 00 为首页总图，PLATE 01–22 为 22 张通路挂图（PLATE 07 为 Cori 循环）。其中 21 张登记在 `src/data/homeMap.ts` 的 `HOME_PATHWAYS`（PLATE 01–06、08–22），Cori 循环单独在 `src/data/pathways.ts` 登记为 PLATE 07。
- 结构对照：**SF-01–22 共 22 页、180 个不重复块**。实测 21 份逐步对照配置共 189 块，SF-07（Cori）的 9 块复用糖酵解 / 糖异生既有块、不重复计数；SF-06（氧化磷酸化）是独立模块页，不套逐步对照器，故不计块。
- 资产：**61 个 3D 资产、206 个证据分子**（`validate-assets` 实测：SMILES 往返 / 分子式 / 分子量 / SVG 键线 / 坐标 / 体积 / gzip / provenance 全通过）。
- 物质层：**182 条物质档案**（`validate-molecule-notes`：182/182 已写）；`/substances` 目录 **111 条**，其中完整条目 61 + 待整理 12 = 73 条有正文，其余条目为索引、链接到档案页（`validate-substances`）。
- 首页总图：节点 **40**、边 **66**、共用节点 **18**、资产别名 **14**（`validate-home` 实测；22 张通路挂图只在首页占标题块，不并入 `SOURCES`）。
- 导航：切换器 **23 条**（22 通路 + 首页）。

## 4. 工作纪律

1. **不做 3D**：新图一律 2D，`threeD.status` 固定 `"not-built"`，只写一句口径说明；不登记 PDB 候选、不留「待结构核验」占位。结构对照块统一用 `evOnly2d`。
2. **不编造**：酶名、EC 号、页码、真题年份、ΔG 数值一律不得编造；查不到就留空或明写「未核实」。ΔG 的 `standard` / `physiological` 必须为 `null`，只保留定性标注。
3. **不放宽断言阈值**：计数、节点数、块数变化时更新**期望值**并在注释里写明为什么变，不得把精确断言改成「至少」。
4. **不 force push**；未经用户明确要求不 commit、不 push。
5. **内容依据**：教材章级（Lehninger 8e / 王镜岩《生物化学》/ 人卫版《生物化学与分子生物学》）或本项目数据层字段；禁止二手博客。
6. 新图出现新物质时，必须同步补 `moleculeProfiles.ts` / `moleculeNotes.ts` / `substances.ts`，并更新对应校验脚本的基线数量；不得只改页面。

## 5. 怎么验证

### 5.1 标准顺序

```bash
npm install                 # Node >= 20
npx tsc --noEmit            # 或 npx tsc --noEmit -p tsconfig.json
npm run build               # build:svg → tsc --noEmit → vite build
npm run preview             # 必须保持 http://localhost:4173 运行
```

另开一个终端跑数据校验与冒烟（冒烟默认连 `http://localhost:4173`，可用 `BASE_URL` 覆盖）：

```bash
node tools/validate-*.mjs   # 逐个执行，任一非零退出即失败
node tools/smoke-*.mjs      # 逐个执行，需 preview 在跑
node tools/audit-layout.mjs --tag after
node tools/smoke-layout.mjs # 必须在上一条之后跑
```

**顺序不能颠倒**：`smoke-layout.mjs` 读取 `preview/layout-audit.json`，并检查 `generatedAt` 新鲜度（默认 120 分钟，可用 `AUDIT_MAX_AGE_MIN` 覆盖）。先跑 audit、再跑 smoke-layout；拿旧报告跑绿会被直接拒绝（exit 2）。

## 7. 已知的坑

1. **构建会重写 3 个糖酵解 SVG**：`npm run build` 的 `build:svg` 阶段会重写 `public/assets/pathways/glycolysis/{glycolysis-liver,glycolysis-muscle,glycolysis-rbc}.svg`。之后 `git status` 可能显示 M，但 `git diff` 内容为零差异（CRLF / stat 缓存）。不要因此回滚或误提交；看 `git diff --ignore-space-at-eol` 确认。
2. **`dist` 有历史哈希残留**：`dist/` 被 `.gitignore` 忽略，但旧构建的带哈希 chunk 会残留，直接统计体积会失真。比较体积前先删除 `dist` 再 build。
3. **`smoke-layout` 依赖审计产物新鲜度**：必须 `audit-layout --tag after` → `smoke-layout`，顺序不能反；超过 120 分钟的报告会被判为旧报告。
4. **首页计数是硬断言**：当前必须精确为 **节点 40 / 边 66 / 共用节点 18 / 资产别名 14**（`validate-home.mjs` 与 `smoke-home.mjs` 双侧校验）。只登记标题块的新图不改这些数；一旦新增真实接口节点，必须同步三处（`homeMap.ts`、`validate-home.mjs`、`smoke-home.mjs`）并写清变化原因。
5. **首页画布高度会顶到**：`HOME_CANVAS.height` 当前 790，PLATE 13 标题在 y=746；标题块间距按 48 递推，PLATE 14 起需要依次扩到 794/842/890/938/986，并同步 `HOME_RESERVED_HEAD` 的「13 / 18」计数，否则 `validate-home` 的「标签都在画布内」会失败。
6. **选择器复用会触发 Playwright strict mode**：历史上新增链接复用了 `.frames-entry`，导致选择器命中多个元素、`smoke-embed` 误报。新图入口请用 `data-testid`，不要用通用 class。
7. **新页不登记 = 静默漏测**：`audit-layout.mjs` 的 `ROUTES` 和 `smoke-layout.mjs` 的 `EXPECT` 是两份手工清单；只加页面不加清单，新页不会被体检。
